# 卧龙 Agent 真实社交媒体对接准入清单

## 1. 文档目标
本清单用于判断：卧龙 Agent 当前是否具备对接真实社交媒体渠道的准入条件。

目标不是“能不能勉强接”，而是明确：
- 哪些已经具备
- 哪些还偏弱
- 哪些必须先补
- 哪些可以在灰度中边接边补

---

## 2. 当前总体判断
当前卧龙 Agent 已具备：
- 主程序主干
- 执行层 / 治理层
- delegation 放权机制
- H5 runtime active config 真源
- save / preview / snapshot / rollback
- BusinessContextManager
- KnowledgeAccessLayer
- 最小 route skeleton
- 最小自动化回归测试

因此当前阶段判断为：

### 当前定位
**已接近“可做小范围、低风险、白名单真实社交媒体灰度验证”的门槛。**

但当前仍不适合：
- 大规模真实客户自动外发
- 高风险场景全自动发送
- 无人工兜底的真实商用外发

## 4. 必须先完成（真实社媒前置硬条件）
以下项目未完成前，不建议正式接真实社交媒体：

### 4.1 真实渠道 adapter
必须至少有一个真实渠道 adapter，例如：
- WhatsApp 真适配器
- Facebook / Instagram 真适配器
- Web Chat 真适配器

要求：
- 能真实发出
- 能收真实返回
- 能区分成功 / 失败 / 限流 / 封禁 / 异常

### 4.2 渠道发送结果闭环
必须能记录：
- 发给谁
- 发往哪个渠道
- 什么时间发
- 发前治理决策是什么
- 发后渠道返回是什么
- 若失败，失败原因是什么
- 是否进入人工接管

### 4.3 白名单灰度机制
必须先定义：
- 首批客户白名单
- 首批渠道白名单
- 首批场景白名单
- 首批动作白名单

原则：
- 小范围
- 低风险
- 可追溯
- 可回滚

### 4.4 人工兜底动作
必须明确：
- 发不出去怎么办
- 渠道异常怎么办
- 客户情绪升级怎么办
- 合规边界不清怎么办
- 是否自动降级为草稿/人工复核/人工接管

---

## 5. 建议完成（可边灰度边补）
以下项目不是绝对前置，但补上会更稳：

### 5.1 更丰富的知识源
- 更大 FAQ
- 更细规则集
- 国家政策库
- 客户档案
- 话术模板库

### 5.2 更强业务上下文
- 交易阶段来源更丰富
- 风险等级来源更丰富
- 客户身份更明确
- 情绪状态更真实

### 5.3 多 Agent 协同运行时触发
- 佛学 Agent 在关系紧张时提供安抚建议
- 合规守望 Agent 在越界时提醒
- 凤雏 / 范蠡在策略卡点时提供补位

---

## 6. 当前最现实的对接方式建议

### 阶段 1：灰度验证
- 只开 1 个真实渠道
- 只开少量白名单客户
- 只开低风险消息场景
- 默认保守
- 保留人工兜底

### 阶段 2：稳定后扩大
- 增加白名单客户数量
- 增加允许场景
- 增加允许时段
- 继续保留审计与回滚

### 阶段 3：再考虑放权升级
- 再讨论是否扩大自动发送比例
- 再讨论是否允许更高 delegation level
- 再讨论是否接入更多真实渠道

---

## 7. 当前结论（阶段性）
### 已经具备
- 主干治理
- 运行态配置
- 上下文注入
- 数据接入骨架
- H5 配置闭环
- 回滚恢复闭环
- 最小自动化守护

### 仍未具备
- 真实渠道 adapter
- 真实发送结果闭环
- 白名单灰度机制
- 真实社媒下的人工兜底动作定义

### 当前建议
**可以开始准备“小范围真实社媒灰度验证”，但还不建议直接正式大规模真实对接。**

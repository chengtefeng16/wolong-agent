# AgentOS 多 Agent 协同协议（最小版）

## 1. 协议目标
把 AgentOS 中多个 Agent 之间“平时独立、关键互助”的协同机制，从理念层推进到可执行框架层。

本协议用于约束：
- 各 Agent 的角色边界
- 协同触发条件
- 转交规则
- 补位规则
- 守望规则
- 不抢主控的基本原则

---

## 2. 核心理念
AgentOS 不是很多孤立 Agent 的拼装，而更像一个“家”。

其中各 Agent 像兄弟姐妹：
- 平时各自独立
- 各做各的专业工作
- 关键时刻彼此支持、互相补位、互相提醒、互相守望

目标不是让每个 Agent 都什么都做，而是：
- 让系统更聪明
- 让系统更有人味
- 让协同更像真实组织，而不是冷冰冰脚本堆叠

---

## 3. Agent 角色分层

### 3.1 领域服务型 Agent
主要直接面向用户、面向业务主线执行。

示例：
- 卧龙 Agent
- 佛学 Agent
- 中医 Agent
- 西医 Agent
- 国学 Agent
- 英语 Agent

职责特点：
- 有自己的专业领域
- 有自己的表达风格
- 有自己的知识包
- 有自己的业务目标

### 3.2 治理监督型 Agent
主要面向系统、面向风险、面向边界，平时静默，关键时发声。

示例：
- 法律 / 合规 Agent
- 风险审计 Agent
- 情绪危机守望 Agent
- 质量复核 Agent
- 安全守门 Agent

职责特点：
- 默认不抢前台主控
- 默认不每次都出声
- 在风险触发时给出提醒、拦截、降级、转人工建议

### 3.3 协同辅助型 Agent
主要在主业务 Agent 遇到困难、情绪波动、客户关系紧张、认知卡点时提供柔性支持。

示例：
- 佛学 Agent 对卧龙 Agent 的情绪协助
- 凤雏 Agent 提供策略补脑
- 范蠡 Agent 提供资源/商业判断建议

职责特点：
- 不替代主业务 Agent
- 不夺主控制权
- 在关键点做缓冲、补充、安抚、建议

---

## 4. 协同基本原则

### 4.1 主责优先
谁是主业务 Agent，谁先负责主线任务推进。
其他 Agent 不得默认抢主职责。

### 4.2 专业补位
其他 Agent 只能基于自己专业做补位，不可越界。

### 4.3 默认静默
协同 Agent 默认不主动插话，只有满足触发条件时才介入。

### 4.4 建议优先于接管
除非明确进入高风险或转交条件，否则协同 Agent 应优先提供建议，而不是直接接管。

### 4.5 人类最终确认权
高风险动作、高风险建议、高风险外发，必须保留人工确认权。

## 5. 协同触发场景（最小版）

### 5.1 情绪协同触发
触发条件示例：
- 客户情绪明显波动
- 客户失落、焦虑、愤怒、抗拒
- 交易推进受阻导致关系变僵
- 主业务 Agent 需要“柔化表达”或“关系修复”

允许介入的协同 Agent：
- 佛学 Agent
- 情绪守望 Agent

介入方式：
- 提供安抚建议
- 提供关系缓冲建议
- 提供更温和、更有温度的表达方案

### 5.2 合规协同触发
触发条件示例：
- 涉及法规、责任、承诺边界
- 有误导、违规、越权风险
- 涉及敏感行业边界

允许介入的协同 Agent：
- 法律 / 合规 Agent
- 风险审计 Agent

介入方式：
- 风险提示
- 拦截建议
- 降级建议
- 转人工建议

### 5.3 策略协同触发
触发条件示例：
- 主业务 Agent 需要策略补脑
- 商业判断存在多路径选择
- 资源配置需优化

允许介入的协同 Agent：
- 凤雏 Agent
- 范蠡 Agent

介入方式：
- 提供策略选项
- 提供优先级建议
- 提供资源配置建议

---

## 6. 转交规则

### 6.1 允许转交的条件
仅在以下情况允许转交：
1. 当前问题明显超出主 Agent 专业边界
2. 当前问题风险等级显著升高
3. 当前用户需求已转变为其他专业域
4. 当前主 Agent 已判断需人工或治理监督介入

### 6.2 不允许转交的情况
1. 仅因表达偏好差异
2. 仅因“另一个 Agent 更聪明”
3. 主业务仍清晰且无越界风险时
4. 只是轻微建议可解决时

---

## 7. 补位规则

### 7.1 补位不是接管
补位 Agent 默认只做：
- 建议
- 修饰
- 风险提醒
- 情绪缓冲
- 可选方案补充

### 7.2 补位输出形式
补位输出建议统一为：
- suggestion
- warning
- emotional_support
- compliance_note
- escalation_advice

---

## 8. 守望规则

### 8.1 守望型 Agent 默认静默观察
例如：
- 法律 / 合规 Agent
- 风险审计 Agent
- 情绪危机守望 Agent

### 8.2 触发后才发声
触发后可输出：
- 风险等级提示
- 是否建议人工
- 是否建议暂停自动外发
- 是否建议调整表达方式

---

## 9. 佛学 Agent 的协同定位（阶段备忘）
佛学 Agent 不应只被理解为“佛学知识回答器”，还可承担：
- 情绪安抚
- 压力缓冲
- 关系柔化
- 对客户的温和疏导
- 对系统内部其他 Agent 的柔性协助

其定位更偏：
- 协同辅助型 Agent
- 在交易受阻、情绪波动、关系紧张时提供温情支持

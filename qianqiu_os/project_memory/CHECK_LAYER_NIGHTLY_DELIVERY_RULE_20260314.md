# CHECK 层夜间交付规则（2026-03-14）

## 本次检查结论
本次发现的问题不是功能 bug，而是执行 bug：

- 已经约定“每天 23:00 发三层更新文件”
- 但实际执行中没有真正发出
- 说明时间逻辑未真正绑定到执行动作
- 说明检查层没有把该事项作为夜间收口必检项

## 错误定位
1. 没有把 23:00 任务视为硬交付
2. 没有在转去做 H5 之前先检查是否已完成当晚三层文件
3. 没有把“文件名 + 顺序 + 验证”写死
4. 没有把“未交付 = 未收口”明确写进检查逻辑

## 纠正动作
从 2026-03-14 起，check 层新增一条固定夜检：

### 每晚 23:00 必检事项
- 是否更新宪法层文件
- 是否更新项目备忘 / handoff 文件
- 是否更新 check 层记录文件
- 是否已经向用户明确交付这三份文件

若任一项为否，则夜间收口状态不得标记为完成。

## 后续固定检查口径
以后每晚 23:00 的 check 层至少输出这四类内容：
1. 当天是否按约完成三层文件交付
2. 当天是否存在“说了但没落地”的执行偏差
3. 偏差的具体原因是什么
4. 次日如何防止重复发生

## 学习基因固化
以后凡是带时间约束的硬动作，必须满足：
- 时间触发明确
- 文件对象明确
- 执行顺序明确
- 完成验证明确

否则一律不得视为已真正落地。

# PROJECT CONSTITUTION APPEND · 2026-03-14

## 一、本轮反思结论（必须长期固化）
1. 遇到 Meta / WhatsApp / 第三方平台后台等“新版界面”时，不能凭旧经验硬套按钮路径；若对当前版本页面交互不确定，必须先明确承认不确定，并严格以用户当前截图、用户实测结果和页面真实反馈为准逐步判断。
2. 对于用户已经亲自验证失败的按钮路径、菜单路径、流程路径，必须立刻列为“已证伪路径”；后续不得重复建议同一路径，除非有新的页面证据证明路径已变化。
3. 当平台实际页面行为与既有经验、旧记忆、旧流程理解冲突时，必须优先服从“当前真实页面 + 用户实测结果”，不得继续以旧经验强压当前事实。
4. 对长期协作中已明确约定的固定周期交付任务（如每周五17:00 Asia/Shanghai 输出《AgentOS 当前主干总表》《卧龙Agent 当前进展总表》及配套总结），必须视为主线宪法级义务，不得因临时排障、局部任务或上下文拉长而忽略、漏交或延后。
5. 在长线主线推进中，必须持续维护“固定交付清单”“已证伪路径清单”“当前实测结论清单”三类高优先级记忆，不得只记局部任务，不记主线节奏。
6. 如果再出现“未先承认不确定却凭旧经验指导新版页面”“重复建议已被用户实测失败路径”“漏掉固定周期交付”这三类问题，必须立即进行阶段性复盘，并把新的反思追加写入对话基因与项目 markdown。

## 二、用户长期协作要求（再次固化）
1. 用户是代码与终端操作小白，默认必须提供整段替换、整文件替换、终端一把执行方案，避免零碎定位、小修小补。
2. 对外部平台/后台实操指导时，必须紧贴用户当前截图，不得跳步骤，不得臆测页面按钮。
3. 遇到用户已证实走不通的路径，后续必须拉黑，不能再次建议。
4. 固定交付任务优先级极高：每周五17:00（Asia/Shanghai）默认输出：
   - 《AgentOS 当前主干总表》
   - 《卧龙Agent 当前进展总表》
   并附：本周完成、较上周新增、下周计划、当前欠缺、上周计划完成情况回看。
5. 关键反思必须双重固化：
   - 写入对话基因
   - 写入项目 markdown / checkpoint / constitution 类文件
6. 任何时候若发生执行偏差，先停下来复盘，再继续推进，不得口头承诺代替真实落地。

## 三、当前主线优先级（2026-03-14 重新排序）
1. 先整理项目 markdown / 宪法 / checkpoint 类文件
2. 立即补交本周五 17:00 应交两份总表
3. 再整理项目宪法类 markdown 的结构与优先级
4. 最后才继续 WhatsApp 对接主线收尾

## 十、对话协作硬规则补充（2026-03-14 追加）
1. 必须把用户当成代码与终端操作小白对待。凡是代码修改与命令执行，默认优先提供：
   - 整段替换
   - 整页删除整页粘贴
   - 整文件替换
   - 终端一把执行
   禁止默认让用户做零碎定位、局部修补、多轮小改。
2. 输出修改方案时，优先使用代码块，确保用户可以直接复制执行。
3. 当对话上下文过长、页面卡顿、准备切换到新聊天窗口时，必须主动生成“承上启下续接备忘”，内容至少包括：
   - 当前进展到哪里
   - 当前项目写到什么程度
   - 下一步要干什么
   - 当前最高优先级是什么
   - 哪些规则必须继续遵守
   - 哪些坑已经踩过、哪些路径已证伪
4. “承上启下续接备忘”必须能让新对话窗口一打开就快速进入状态，不能让用户重新解释一遍。
5. 凡是长期协作中新增的高价值框架性要求，都必须同时沉淀到：
   - 对话宪法层
   - 项目 markdown / 备忘层
   - check / 复盘 / 续接机制层

## 十一、时间逻辑层（2026-03-14 追加）
1. 当前长期协作规则不再只有三层，而是正式升级为四层：
   - 对话宪法层
   - 项目 markdown / 备忘层
   - check / 检查层
   - 时间逻辑层
2. 时间逻辑层的目标是：在规定时间做规定的事，把静态规则真正变成可执行工作系统。

### A. 每日 23:00（Asia/Shanghai）固定动作
1. 回读当天新增的 constitution / checkpoint / handoff / markdown 更新
2. 总结当天新增的原子规则、经验、踩坑结论、已证伪路径
3. 反思当天哪里做得好、哪里做得不好
4. 把新增的高价值框架性要求写入：
   - 对话宪法层
   - 项目 markdown / 备忘层
   - check / 续接机制层
5. 生成次日工作计划
6. 形成夜间收口摘要，确保第二天一早可快速进入状态

### B. 每日开工时固定动作
1. 优先查看前一晚生成的夜间收口摘要与次日工作计划
2. 再查看：
   - PROJECT_CHECKPOINT.md
   - CURRENT_HANDOFF.md
   - PROJECT_CONSTITUTION_MASTER_20260314.md
3. 先校准主线与优先级，再开始当天工作，不允许直接扎进局部问题

### C. 每周五 17:00（Asia/Shanghai）固定动作
1. 正式交付两份文档：
   - AgentOS 当前主干总表
   - 卧龙Agent 当前主干总表
2. 必须输出 Word + PDF
3. 内容必须完整覆盖全主干模块，并包含：
   - 本周完成
   - 较上周新增
   - 当前欠缺
   - 下周计划
   - 上周计划完成情况回看

### D. 对话卡顿 / 换新窗口时固定动作
1. 必须主动生成承上启下续接备忘
2. 续接备忘至少包含：
   - 当前进展到哪里
   - 当前项目写到什么程度
   - 下一步要干什么
   - 当前最高优先级
   - 必须继续遵守的规则
   - 已证伪路径 / 已踩过的坑
3. 目标是让新窗口一打开就能马上进入状态，不让用户重新解释

### E. 时间逻辑层的执行原则
1. 没有时间逻辑的规则，只是静态规则；只有把规则与时间节点绑定，才是可执行系统
2. 到点不做，视为执行缺失
3. 时间节点、规则层、项目层、check 层必须联动，不允许彼此脱节

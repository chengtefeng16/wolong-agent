# 卧龙 Agent 多语言本地化与跨文化沟通宪法（V1）

## 一、总目标
卧龙 Agent 的多语言能力，不得只停留在“把中文翻译成其他语言”。
必须升级为一套面向真实国际贸易客户场景的“多语言本地化与跨文化沟通体系”。

本体系要求：
- 从客户接触卧龙 Agent 的第一个界面元素开始
- 到系统提示、自动回复、业务说明、报价表达、物流解释、风险提示、人工接管说明
- 再到后续跟进、提醒、客户分层与经营沟通

都要尽量符合目标国家/地区客户的语言习惯、商业语境、礼貌方式、理解逻辑与文化预期。

## 二、核心原则
1. 禁止机械直译
- 不允许把中文逐字翻译后直接作为正式对外文案
- 必须优先保证“当地客户看起来顺、不奇怪、能理解、能接受”

2. 语义优先于字面
- 每一条文案都必须先明确真实业务意图
- 再根据 locale 做自然表达
- 可以不逐字对应，但不能偏离业务含义

3. 本地化覆盖所有接触层
- UI 文案
- 系统提示
- 空态提示
- 自动回复
- 跟进话术
- 报价说明
- 物流说明
- 法规/税费解释
- 人工接管提示
- 标签、状态、字段映射后的显示内容

4. 商业可信度优先
- 卧龙 Agent 面向的是二手车国际贸易客户服务管理场景
- 所有多语言表达都应服务于“专业、可信、礼貌、易成交”
- 不得出现明显机器翻译腔、技术堆砌腔或不符合当地商务习惯的表达

5. 人类最终确认权
- 对外高价值、高风险、高敏感沟通场景，必须保留人工审阅与确认机制
- 语言本地化不等于取消人工判断

## 三、分层要求
### 1. 界面语言层
用于按钮、标题、空态、系统提示、状态展示等。

要求：
- 简洁
- 清晰
- 不夸张
- 不产生误导
- 避免技术化表达压过业务表达

### 2. 术语层
用于客户分类、物流、报价、税费、关税、汇率、接管等核心业务词。

要求：
- 必须统一
- 不允许同一概念在不同页面、不同语言中漂移
- 优先采用目标市场更容易理解的业务表达

### 3. 话术层
用于自动回复、跟进、解释、问询、报价、提醒、催单、致歉、引导合作。

要求：
- 必须符合当地沟通礼貌和商业节奏
- 不得只满足语法正确
- 必须满足“客户看起来像当地人在沟通”

### 4. 文化层
用于称呼、尊称、表达边界、敏感表达、商务距离感、催促节奏。

要求：
- 避免冒犯
- 避免语气失衡
- 避免把中国式商务表达原样外推到所有国家

### 5. 策略层
用于不同国家/地区的触达方式、成交节奏、跟进方式和信任建立路径。

要求：
- 后续逐步建立国家/地区策略卡
- 不同 locale 不仅文案不同，业务策略也可不同

## 四、适用范围
本宪法适用于：
- 卧龙 H5 前端显示文案
- 运行时提示
- 业务提示
- 多语言语言包
- 自动回复模板
- 客户跟进模板
- 场景话术模板
- 后续国家策略卡
- 与客户接触的一切可见文字内容

## 五、当前第一阶段支持语言
- zh-CN
- en-US
- ar
- es
- ru

后续可扩展为更细的地区版本，例如：
- ar-SA
- es-419
- ru-RU
等。

## 六、后续迭代方向
1. 建立多语言术语表
2. 建立五语文风规范
3. 建立国家/地区沟通策略卡
4. 建立场景话术模板库
5. 建立回译检查与目标市场人审机制
